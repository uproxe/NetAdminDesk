# Участие в разработке

Спасибо, что хотите помочь NetAdmin Desk. Ниже — как устроена работа с репозиторием.

## Сообщить об ошибке или предложить идею

- Ошибка — [Issues → «Сообщить об ошибке»](../../issues/new/choose). Укажите версию программы, ОС, шаги и что ожидали увидеть.
- Неверная команда в справочнике — тот же шаблон: платформа, модель и версия прошивки, команда и правильный вариант.
- Уязвимость — **не создавайте публичный issue**, см. [политику безопасности](.github/SECURITY.md).

Не прикладывайте конфигурации, журналы и снимки экрана с реальными адресами, именами, паролями и community — замените их нейтральными примерами (`192.0.2.10`, `SW-ACCESS-1`).

## Подготовка окружения

```bash
npm install --ignore-scripts
node node_modules/electron/install.js   # бинарник Electron для локального запуска
npm test                                 # модульные тесты
npm start                                # сборка и запуск
```

Требуется Node.js 22.5 или новее. Подробнее о сборке установщиков — в [docs/BUILD.md](docs/BUILD.md).

## Ветки и коммиты

- Основная ветка — `main`, она всегда собирается и проходит тесты. Работайте в своей ветке: `feat/…`, `fix/…`, `docs/…`.
- Сообщения коммитов — по [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/): `тип(область): что сделано`, описание — по-русски.

  | Тип | Когда |
  |---|---|
  | `feat` | новая возможность |
  | `fix` | исправление ошибки |
  | `docs` | документация и руководства |
  | `test` | тесты |
  | `refactor` | переработка без изменения поведения |
  | `build`, `ci` | сборка, GitHub Actions |
  | `chore` | прочее (версия, служебные файлы) |

  Примеры: `feat(monitor): трапы linkDown/linkUp`, `fix(ssh): повторное подключение после смены ключа`.
- Один коммит — одно логическое изменение.

## Перед pull request

```bash
npm test
npm run typecheck
```

- Новые команды справочника: если синтаксис не проверен на оборудовании, запись должна быть помечена «Требует проверки» (`sure: false`) — так работают все встроенные записи, кроме Cisco IOS.
- Справочник обезличен: тест `проект обезличен` не пропускает реальные адреса и названия.
- Изменения, заметные пользователю, — строка в разделе `[Unreleased]` файла [CHANGELOG.md](CHANGELOG.md).

## Требования безопасности

Это инструмент администратора, поэтому некоторые правила не обсуждаются:

- пароли, ключи, community и пароли SMTP не хранятся открытым текстом и не пишутся в журналы;
- проверка ключей хостов SSH не отключается ради удобства;
- команды не выполняются незаметно в фоне, изменяющие команды подтверждаются, `sudo` не подставляется автоматически;
- предположение не выдаётся за установленный факт: непроверенное помечается как непроверенное.

## Выпуск версии

1. Перенести пункты из `[Unreleased]` в новый раздел `## [X.Y.Z] — ГГГГ-ММ-ДД` в CHANGELOG.md, обновить ссылки внизу файла.
2. Обновить версию в `package.json` и `VERSION`.
3. Коммит `chore(release): X.Y.Z`, аннотированный тег `vX.Y.Z`, `git push --follow-tags`.
4. GitHub Actions соберёт установщики и опубликует релиз с текстом из CHANGELOG.

Версии — по [семантическому версионированию](https://semver.org/lang/ru/).
