# Резервное копирование и восстановление

## Что хранит программа

| Файл / каталог | Содержимое |
|---|---|
| `netadmin.db` | Устройства, группы, справочник (включая ваши правки и импорт), сценарии, заметки, история, отчёты диагностики, известные ключи хостов, настройки, **зашифрованные** пароли |
| `backups/<устройство>/*.cfg` | Снятые конфигурации коммутаторов |
| `backups/<устройство>/files_<дата>/` | Файлы Linux, загруженные по SFTP, с `MANIFEST.txt` |
| `auto-backups/netadmin-ГГГГ-ММ-ДД.db` | Ежедневные автоматические копии базы (14 последних) |
| `session-logs/` | Журналы сессий (только если включены) |

Расположение каталога — в «Настройки → База данных» (кнопка «Открыть каталог») и в [USER_GUIDE.md](USER_GUIDE.md#1-первый-запуск).

## Автоматические копии

При каждом запуске, если за сегодня копии ещё нет, база копируется в `auto-backups/`. Хранятся 14 последних. Восстановление: «Настройки → База данных → Автоматические копии → Восстановить». Текущая база перед заменой сохраняется рядом с суффиксом `.before-restore`, затем программа перезапускается.

Если при запуске проверка целостности базы не проходит, программа сама предложит восстановить последнюю автокопию.

## Ручная копия базы

«Настройки → База данных → Сохранить копию базы…» — копия файла `netadmin.db` в выбранное место. Восстановление — «Восстановить из файла…» (проверяется, что это база SQLite; текущая сохраняется как `.before-restore`).

Можно копировать и весь каталог данных целиком при закрытой программе.

> **Пароли в копии базы.** В копии базы пароли зашифрованы тем же способом, что и в рабочей базе:
> - в режиме **мастер-пароля** копию можно восстановить на любом компьютере — понадобится тот же мастер-пароль;
> - в режиме **системного хранилища** (DPAPI / Keychain / libsecret) пароли расшифровываются только той же учётной записью на том же компьютере. На другом компьютере устройства восстановятся, но пароли придётся ввести заново. Для переноса используйте зашифрованный экспорт ([MIGRATION.md](MIGRATION.md)).

## Зашифрованная полная копия (.nadx)

«Настройки → Импорт и экспорт → Зашифрованный экспорт всех данных…» — один файл со всеми данными, **включая пароли**, известные ключи хостов и настройки; по желанию — историю. Шифрование AES-256-GCM, ключ из пароля файла (scrypt). Подходит и как резервная копия, и для переноса между ОС.

Храните файл и его пароль раздельно. Без пароля файл восстановить невозможно.

## Экспорт без паролей (JSON / TXT)

- JSON — команды, сценарии, заметки, группы, карточки устройств без паролей. Удобно для обмена с коллегами.
- TXT — ваши записи справочника в исходном виде (записи с учётными данными не экспортируются).

## Резервные копии конфигураций устройств

Файлы в `backups/` — обычные текстовые файлы, их можно копировать, архивировать и хранить в системе контроля версий. Список копий и связь с устройствами хранится в базе; при удалении записи в программе можно удалить и файл (отдельная отметка).

## Рекомендуемый порядок

1. Мастер-пароль или системное хранилище — по вашим требованиям.
2. Раз в неделю — зашифрованный экспорт `.nadx` на внешний носитель или в защищённое хранилище.
3. Каталог `backups/` — в общее резервное копирование вместе с остальными конфигурациями сети.
