# Безопасность NetAdmin Desk

## Пароли и секреты

- Пароли, парольные фразы ключей и enable-пароли хранятся в таблице `secrets` **только в зашифрованном виде**:
  - `os` — `safeStorage` Electron: DPAPI (Windows), Keychain (macOS), libsecret/KWallet (Linux);
  - `master` — AES-256-GCM, ключ 256 бит из мастер-пароля через scrypt (N = 2^15, r = 8, p = 1), соль и проверочное значение хранятся в базе, сам мастер-пароль — нигде;
  - `prompt` — пароли не сохраняются.
- На Linux backend `basic_text` (нет связки ключей) считается небезопасным: в этом режиме пароли не сохраняются, программа предлагает мастер-пароль.
- В JSON-экспорт, TXT-экспорт, журналы и историю пароли не попадают. Зашифрованный экспорт `.nadx` содержит пароли, зашифрованные паролем файла (AES-256-GCM + scrypt, данные заголовка защищены как AAD).
- CSV-импорт берёт пароли только при явной отметке пользователя; при импорте `~/.ssh/config` пароли не читаются (их там нет), опасные параметры (устаревшие алгоритмы) показываются в предварительном просмотре.
- Записи TXT с учётными данными (например, пароли по умолчанию) помечаются как чувствительные, скрываются из поиска и карточек и не экспортируются в TXT.

## Мониторинг сети

- **Секреты мониторинга** — community SNMP каждого узла, пароль SMTP и community для приёма трапов — хранятся в таблице `app_secrets` только в зашифрованном виде, тем же способом, что и пароли устройств (`os` или `master`). Если надёжного хранилища нет (режим «спрашивать каждый раз», Linux без связки ключей, хранилище заблокировано), программа **отказывается сохранять** community, а не пишет её открытым текстом; узел тогда проверяется по ping. При смене режима хранилища секреты перешифровываются, при переходе в режим «спрашивать» — удаляются. В список узлов, события, письма и журналы секреты не попадают.
- **Что программа отправляет на устройства**: ping, подключение к TCP-порту и SNMP-запросы только на чтение (GET, GETNEXT, GETBULK: sysUpTime, sysName, sysDescr, таблица интерфейсов). SNMP SET не используется, команды по SSH мониторинг не выполняет.
- **SNMP v1/v2c не шифруют трафик**, community передаётся открытым текстом — это свойство протокола. Используйте отдельную community только для чтения и разрешайте опрос только с адреса компьютера с программой. SNMPv3 не поддерживается.
- **Приём трапов** выключен по умолчанию. Когда включён, программа слушает UDP-порт (по умолчанию 162) на выбранном адресе. Трап только записывается в журнал событий и меняет отметку узла (порт отключился или включился, перезагрузка): трапы ничего не запускают и не меняют настройки. Можно принимать трапы только с указанной community; трапы от адресов, которых нет в мониторинге, записываются не чаще раза в минуту для одного адреса и типа трапа. Ответ отправляется только на inform (подтверждение получения).
- **Почта**: STARTTLS или TLS с проверкой сертификата; отключить проверку можно только явно («Не проверять сертификат сервера», для своего внутреннего сервера). Пароль SMTP передаётся только после установки шифрования, если выбран STARTTLS/TLS.
- **Работа в фоне** видна: значок в области уведомлений с числом узлов не в сети, при первом сворачивании — уведомление. Автозапуск включается только в настройках.

## Менеджер паролей

- **Отдельный мастер-пароль.** Ключ вычисляется scrypt (N=2¹⁷, r=8, p=1, соль 16 байт; около 128 МБ памяти) в пуле потоков, мастер-пароль нигде не сохраняется. Для проверки пароля хранится контрольная строка, зашифрованная этим ключом (`meta.pm_master`), — по ней пароль проверяется, но не восстанавливается.
- **Что зашифровано.** Каждая запись целиком (название, логин, пароль, адрес, заметки, метки, папка, избранное, даты, история паролей) и название каждой папки — отдельный blob AES-256-GCM со случайным IV. В качестве AAD используется идентификатор строки: blob, переставленный в другую строку или изменённый, не расшифруется, и менеджер не откроется. Открытым остаётся только число записей и папок.
- **В памяти.** Ключ и расшифрованные записи живут в main-процессе, пока менеджер открыт; при блокировке буфер ключа затирается нулями, записи удаляются из памяти. Интерфейс получает список без паролей и заметок; пароль — только по «Показать» (в окне скрывается через 30 секунд) или при открытии редактора записи.
- **Буфер обмена.** Копирование идёт через main-процесс; пароль удаляется из буфера через заданное время (по умолчанию 20 с), при блокировке и выходе — только если в буфере всё ещё он.
- **Блокировка**: кнопкой; после заданного времени без действий; при блокировке экрана и переходе в сон (powerMonitor); по желанию — при сворачивании и скрытии окна.
- **Подбор пароля.** После трёх неверных попыток — пауза 1, 2, 4… до 30 с. Это защищает от подбора через интерфейс; от подбора по копии базы защищает только стоимость scrypt и длина мастер-пароля.
- **Восстановления нет.** Забытый мастер-пароль восстановить нельзя; можно удалить все записи (подтверждение словом «УДАЛИТЬ»).
- **Экспорт .nadpass** — тот же формат шифрования (scrypt + AES-256-GCM) с паролем файла не короче 8 символов. **Экспорт CSV** — открытым текстом, только после предупреждения, отметки «Понимаю» и повторного ввода мастер-пароля.
- **Импорт** только с предпросмотром: записи (без паролей) показываются до добавления, пользователь выбирает, что импортировать; совпадающие записи по умолчанию не выбраны. Расшифрованные строки импорта хранятся в памяти до импорта, отмены или блокировки.
- Записи менеджера паролей не попадают в «Перенос данных» и журналы; в резервной копии базы данных — только в зашифрованном виде.

## Перенос устройств (.nadevices)

- Без отметки «Сохранённые пароли» файл переноса содержит только карточки устройств, группы и (по выбору) открытые ключи хостов — паролей в нём нет, и он не шифруется.
- С отметкой «Сохранённые пароли» экспорт без пароля файла невозможен: весь файл (включая адреса и имена устройств) шифруется AES-256-GCM, ключ — из пароля файла через scrypt, как в `.nadx`. Пароль файла не сохраняется.
- При импорте пароли записываются в хранилище только по отдельной отметке пользователя и только если хранилище настроено и разблокировано; иначе они пропускаются (программа сообщает сколько).
- Ключи хостов из файла добавляются только для адресов, которых на этом компьютере ещё нет. Если ключ для адреса уже известен и отличается, он **не заменяется** — подмена ключа через подложенный файл невозможна; расхождение показывается в просмотре.
- CSV-экспорт устройств паролей не содержит.

## Базы данных

- В истории маскируются пароли SQL: `IDENTIFIED BY '…'`, `PASSWORD '…'`, `PGPASSWORD=…`, `-p…` и `--password=…` клиента mysql.
- Оценка риска SQL — по операторам: `DROP`, `TRUNCATE`, `DELETE`/`UPDATE` без `WHERE`, восстановление дампа поверх базы, `dropdb` — «Опасно» или «Критично» и требуют подтверждения. Оценка эвристическая.
- Диагностика баз данных выполняет только запросы на чтение (`SHOW`, `SELECT` из системных представлений) и команды просмотра; `sudo` не используется. Под root вход идёт через сокет MySQL / MariaDB или от имени `postgres` через `runuser` — это права, которые у сеанса уже есть. Найденные проблемы сопровождаются командами (отмена запроса, удаление слота), но сами они не выполняются.

## SSH

- Ключ хоста проверяется при каждом подключении. Новый ключ — запрос с отпечатком SHA256; изменившийся ключ — подключение блокируется, замена возможна только явным действием с подтверждением сверки. Принятие и замена ключей записываются в историю.
- Проверку ключей нельзя отключить в настройках.
- Устаревшие алгоритмы (`diffie-hellman-group1/14-sha1`, `ssh-rsa`, `ssh-dss`, CBC-шифры, `hmac-sha1`, `hmac-md5`) включаются только для конкретного устройства и добавляются в конец списка — современные алгоритмы остаются приоритетными.
- Агент SSH используется только при выборе метода «SSH-агент»; пересылка агента не включается.

## Telnet и COM-порт

- **Telnet не шифрует трафик**: логин, пароль и вывод видны в сети. Протокол включается только в карточке конкретного устройства; глобально ничего не меняется. Предупреждения — в карточке, на вкладке («TELNET») и на панели сессии («Telnet без шифрования»), при импорте из CSV.
- Пароль для Telnet берётся только из защищённого хранилища и отправляется лишь в ответ на запрос «Password:» в течение 30 секунд после подключения; в историю не записывается.
- COM-порт открывается через Web Serial. Разрешено только обращение к последовательным портам (проверка разрешений отклоняет всё остальное), порт выбирается по имени из карточки устройства. Всё, что идёт через порт, проходит через ту же сессию, что и SSH: история, маскировка паролей, «Только чтение».

## Несколько сессий

- «Ввод во все» работает только для панелей, видимых в разделённом экране; включается с подтверждением, пока он активен — красная полоса со списком устройств.
- Окно команд оценивает риск до отправки. Изменяющие команды сразу в несколько сессий подчиняются той же настройке «Массовое выполнение», что и сценарии (по умолчанию запрещено).
- Команды после входа (карточка устройства) отправляются видимо и проверяются режимом «Только чтение».

## Сетевые утилиты и SSH-ключи

- Ping, трассировка и проверка портов запускаются только по кнопке; точная команда показывается. Адрес проверяется (только имя узла или IP), программа запускается без оболочки — подстановка аргументов невозможна.
- Созданный приватный SSH-ключ записывается только в выбранный файл (права 600 в Linux и macOS) и не передаётся в интерфейс. Существующий файл не перезаписывается. Установка открытого ключа на сервер — через обычное окно проверки команды.

## Выполнение команд

- Ни одна команда не отправляется на устройство незаметно: ввод виден в терминале, итоговая команда показывается перед отправкой.
- Каждая команда оценивается по риску («Просмотр», «Изменение», «Опасно», «Критично»); изменяющие и многострочные команды требуют подтверждения. Оценка эвристическая — это подсказка, а не гарантия.
- Несовместимая платформа блокирует отправку до явного подтверждения.
- Режим «Только чтение» (глобальный или для устройства) блокирует изменяющие команды из справочника, сценариев и диагностики.
- Массовое выполнение изменяющих сценариев по умолчанию запрещено.
- Диагностика Linux использует только команды чтения; `sudo` автоматически не используется.

## История и журналы

- В историю записываются отправленные команды с маскировкой паролей (`password …`, `secret …`, `-p…` у mysql, `--password=…`, `user:pass@` в URL и т. п.).
- Строки, введённые после запроса пароля устройства, не записываются.
- Журналы сессий выключены по умолчанию. Если включить, в них попадает всё, что выводит устройство.

## Приложение

- Интерфейс работает с `contextIsolation`, `sandbox`, без `nodeIntegration`; доступно только перечисленное в `src/shared/ipc.ts` API.
- Политика безопасности содержимого (CSP) запрещает загрузку внешних скриптов и сетевые запросы из интерфейса.
- Новые окна и переходы по ссылкам внутри приложения запрещены; http(s)-ссылки открываются во внешнем браузере.
- Запросы разрешений (камера, геолокация и т. п.) отклоняются; из проверок разрешений проходит только доступ к COM-портам.
- Телеметрии и обращений в интернет нет. Сетевые обращения — только к вашим устройствам, узлам мониторинга и указанному вами SMTP-серверу.

## Браузер NetLoom в установщике Windows

- Необязательный шаг: галочка «Также установить браузер NetLoom» по умолчанию снята; без неё установщик в интернет не обращается.
- Если галочка отмечена, установщик скачивает NetLoom по https с github.com (адрес закреплён при сборке, менять его при установке нельзя) и проверяет SHA-256 файла по значению, зашитому в установщик. При несовпадении файл удаляется и не запускается.
- Загрузку и проверку выполняет сценарий `build/netloom-install.ps1` через Windows PowerShell; политика выполнения ослабляется только для этого процесса (`-ExecutionPolicy Bypass`), системные настройки не меняются. Если PowerShell запрещён групповой политикой, NetLoom не ставится, установщик сообщает причину.
- NetLoom ставится от имени пользователя, без прав администратора — даже если NetAdmin Desk устанавливается «для всех пользователей».

## Сборки

Установщики не подписаны сертификатами разработчика (см. [BUILD.md](BUILD.md)). Проверяйте контрольные суммы `.sha256`, публикуемые рядом с установщиками на странице релиза.
