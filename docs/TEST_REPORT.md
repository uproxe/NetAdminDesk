# Отчёт о тестировании — версия 1.0.0

Дата: 18.11.2026.

## Что сделано в 1.0.0 и как проверено

Проверено здесь (Linux-контейнер без интернета, см. «Среда разработки» ниже):

- **Модульные тесты: 83 из 83.** Новые: диагностика баз данных (разбор вывода всех 13 проверок: подключения на пределе, недавний перезапуск, долгие запросы, остановленная реплика, повреждение в журнале, заполненный диск, неудачные настройки, блокировки, неактивный слот, возраст транзакций; «нет клиента», «нет доступа», «сервер не отвечает»; на сервере без MySQL все проверки MySQL отвечают «не установлен»; команды без sudo и без изменяющих операторов), перенос устройств (выбор устройств, автоматическое добавление узла-посредника, вложенные группы, ключи хостов, повторный импорт без дублей, зашифрованный файл без открытого текста, неверный пароль, пароли не импортируются без согласия, отличающийся ключ хоста не заменяется, импорт устройств из полной копии, CSV с BOM, кавычками, запятыми и «;» читается обратно), обновление базы до 1.0 (старые записи TXT удаляются, свои правки и избранное сохраняются, команды БД переезжают в раздел SQL), таблицы в руководствах, маскировка паролей SQL в кавычках, обезличенность справочника.
- **Настоящий PostgreSQL 16.15** (одноразовый локальный кластер в среде сборки — не рабочий сервер):
  - все 6 проверок PostgreSQL выполнены теми же командами, что отправляет программа: под root в bash и в dash, под пользователем без роли в PostgreSQL («нет доступа» с подсказкой), при остановленном сервере («не отвечает», «кластер 16 main не работает»). Созданы проблемы — 66 соединений, запрос, заблокированный `LOCK TABLE`, запросы дольше минуты, таблица с 270 тыс. «мёртвых» строк при выключенной автоочистке, неактивный слот репликации — каждая найдена;
  - справочник: **88 SQL-операторов** записей PostgreSQL и «общего SQL» (команды и примеры) выполнены на тестовых данных — все успешно. Сначала было 8 ошибок: 4 — конфликты с тестовыми данными, 4 — настоящие ошибки справочника (три записи «общего SQL» с синтаксисом только MySQL и запрос к pg_stat_statements), исправлены (см. ниже);
  - **22 команды оболочки** (pg_dump, pg_dumpall, pg_restore, createdb, vacuumdb, pg_basebackup, psql -c / -f, pg_lsclusters, pg_ctlcluster…) выполнены — все успешно после исправлений. Не запускались: nano, systemctl, apt (в контейнере нет systemd), `ss` (нет утилиты), подключения к удалённому адресу;
  - 18 блоков PostgreSQL из руководств выполнены успешно;
  - вывод проверок PostgreSQL для снимков экрана снят с этого же сервера (`tools/preview/db-sample.ts`).
- **Интерфейс в Chromium** (предпросмотр с имитацией API), 57 шагов без ошибок консоли; новые шаги: справочник SQL, окно выполнения `DROP DATABASE` (риск «Критично», напоминание открыть клиент базы, предупреждение о коммутаторе), диагностика PostgreSQL и MySQL («не установлен»), руководство с таблицей отличий, экспорт устройств (файл переноса и CSV), импорт «С другого компьютера» с просмотром, Ctrl+K находит команды SQL и действие «Экспорт устройств», свёрнутая панель. Все разделы сняты в обеих темах без ошибок.
- **Свёрнутая панель** измерена в браузере: четыре кнопки внизу — 30×30 пикселей, центры на x = 28,5, на той же оси, что и значки меню.

Найдено этой проверкой и исправлено:

- Ctrl+K не показывал команды SQL (группа не входила в порядок вывода).
- Проверки служб (базы данных, веб-серверы, firewall) склеивали строки, когда systemctl ничего не выводил, и сообщали «служба не работает» — замечено при запуске в контейнере без systemd.
- Справочник SQL: `round(mean_exec_time, 1)` не работает в PostgreSQL (нужно `::numeric`); `psql -U … -f` падал на peer-аутентификации (добавлен `-h localhost`); `pg_basebackup` минутами ждал контрольной точки (добавлен `-c fast`); записи «общего SQL» `DROP INDEX … ON`, `INTERVAL 1 DAY` и обратные кавычки работают только в MySQL — разделены по СУБД или заменены стандартной записью.

**Не проверено и требует проверки на вашей стороне:**

- **MySQL и MariaDB — ни одна команда не выполнялась на настоящем сервере**: в этой среде их нет и установить нельзя (нет интернета). 94 записи «MySQL / MariaDB» написаны по документации; 7 проверок MySQL проверены только модульными тестами на образцах вывода. Проверьте на сервере: «Диагностика → Linux → MySQL / MariaDB: полная проверка» под root и под обычным пользователем, затем несколько команд справочника.
- Проверки PostgreSQL запускались локально (bash, dash), а не через SSH-канал программы — команды те же, но сам канал exec с ними не проверялся. Проверки, зависящие от systemd (службы), — только на образцах.
- Перенос устройств проверен модульными тестами на `node:sqlite`; окна выбора файла Electron, хранилище паролей ОС и перенос между Windows и Linux не проверялись (нет Electron).
- Изменения 1.0.0 в CI ещё не запускались; установщики не собирались здесь. На реальных коммутаторах, серверах и COM-портах программа здесь не проверялась.

- **COM-порт** — нет оборудования и Electron: открытие порта через Web Serial, выбор порта по имени, чтение и запись, отключение кабеля. ## 3. Не проверялось

- **Реальные коммутаторы** — ни одно устройство (Cisco, SG300, HP ProCurve, Linksys, AT-8000S, Allied Telesis, Qtech, OSNOVO, TP-Link) не было доступно. Не проверены на оборудовании: синтаксис встроенных команд и профилей диагностики, распознавание приглашений и `--More--`, автоматический `enable`, отключение постраничного вывода, снятие конфигурации, разбор реальных MAC-таблиц и CDP/LLDP (разборщики проверены только на образцах вывода в тестах).
- **Реальные Linux-серверы** — кроме контейнера OpenSSH в CI.
- Старые SSH-реализации коммутаторов с устаревшими алгоритмами; Jump Host (в том числе перенос связи с Jump Host при импорте); удалённый и SOCKS-туннели; SFTP с большими файлами.
- Системные хранилища паролей на настоящих рабочих станциях (DPAPI, Keychain, GNOME Keyring / KWallet).
- Поведение SmartScreen и Gatekeeper с неподписанными сборками.
- Экранные дикторы, масштабирование HiDPI на разных ОС, длительная работа под нагрузкой.

Перед использованием в рабочей сети рекомендуется проверить на одном тестовом коммутаторе каждой модели: подключение, снятие конфигурации, 2–3 команды просмотра из справочника и диагностику порта.
