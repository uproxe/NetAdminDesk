# Отчёт о тестировании — версия 1.4.0

Дата: 25.11.2026.

## Что сделано в 1.4.0 и как проверено

**Модульные тесты: 117, из них 116 пройдены, 1 пропущен** (настоящий ping — в контейнере разработки нет утилиты ping; в CI проходит). Новый `tests/unit/installer.test.ts`: адрес, сумма и размер закреплённой версии NetLoom согласованы; файлы установщика с русским текстом сохранены в UTF-8 с BOM; галочка NetLoom по умолчанию снята и есть предупреждение про интернет; заданы цели deb, rpm, pacman и AppImage. Проверка типов — 0 ошибок; интерфейс в Chromium (57 шагов) — без ошибок консоли.

**Пакеты Linux — проверено в CI на GitHub Actions:**

- собраны `.deb`, `.rpm`, `.pacman` и AppImage; установленный `.deb` и AppImage (запуск без установки) прошли самопроверку программы на раннере Ubuntu 24.04;
- каждый пакет поставлен штатным менеджером пакетов в чистый контейнер — **Debian 13, Ubuntu 24.04, Fedora, Rocky Linux 9, openSUSE Tumbleweed, Arch Linux**: зависимости разрешились из репозиториев дистрибутива, `ldd` не нашёл недостающих библиотек, самопроверка программы прошла;
- проверка установкой нашла ошибку, которая была и в выпущенном 1.3.0: на чистой Ubuntu 24.04 `.deb` подтягивал `liboss4-salsa-asound2` вместо настоящей библиотеки ALSA, и программа не запускалась (`undefined symbol: snd_device_name_get_hint`). После исправления порядка зависимостей Ubuntu 24.04 проходит.

**Установщик Windows с NetLoom — проверено в CI (Windows Server, раннер GitHub):**

- скрипт установщика собирается NSIS той же версии, что в electron-builder 26.18, с флагом «предупреждения — ошибки»; дополнительно — локально тем же makensis в обвязке, повторяющей порядок подключения заголовков electron-builder;
- сценарий загрузки отклоняет неверную контрольную сумму (файл удаляется), несуществующий адрес и адрес не по https; при загрузке настоящего файла его SHA-256 совпала с закреплённой;
- тихая установка `/S /NETLOOM=1` скачала NetLoom 1.0.3, проверила сумму и установила его (есть в списке программ, `netloom.exe` на месте), NetAdmin Desk при этом остался установлен; журнал `%TEMP%\NetAdminDesk-NetLoom.log` содержит все шаги по-русски;
- снимок шага «Дополнительно» на Windows: галочка снята, описание NetLoom, жирное «Понадобится интернет» с пояснением, логотип в заголовке. Кнопки на снимке английские, потому что язык системы раннера — английский; на русской Windows установщик выбирает русский.
- по пути исправлены две ошибки, которые нашёл CI: сборка падала, потому что electron-builder 26.18 не подключает WordFunc; проверка суммы падала, когда установщик запущен из PowerShell 7 (Windows PowerShell 5.1 наследовал чужие пути модулей и не мог загрузить `Get-FileHash`) — теперь сумма считается средствами .NET.

**Удаление программы и кнопка релиза:**

- деинсталлятор и установщик собираются тем же makensis с флагом «предупреждения — ошибки» (в том числе отдельная сборка деинсталлятора с `BUILD_UNINSTALLER`); в CI на Windows проверено: повторная установка поверх (как обновление) данные в `%APPDATA%\NetAdmin Desk` сохраняет, а тихое удаление программы удаляет и программу, и каталог данных;
- автоматический перезапуск задач без машины проверен на настоящих данных GitHub: попытки 1–5 релиза 1.3.0 (macOS отменён без машины и шагов) — решение «перезапустить», попытка 6 — «всё прошло»; задача с настоящей ошибкой — «не перезапускать». Сам перезапуск через GitHub проверяется на первом же запуске, где GitHub не выделит машину;
- публикация релиза без ожидания macOS и добавление `.dmg` позже (задание `release-mac`) добавлены в CI; проверить их можно только настоящим выпуском, поэтому здесь они не запускались;
- кнопка «Выпустить релиз» добавлена в CI, но запускается вами: из этой среды создавать теги и релизы нельзя, поэтому сам выпуск кнопкой здесь не проверялся.

**Не проверено и требует проверки на вашей стороне:**

- страница-предупреждение деинсталлятора видна только при удалении с окнами — в CI удаление тихое, страница проверена сборкой, а не глазами;
- установка «для всех пользователей» с вводом пароля другой учётной записи администратора: NetLoom в этом случае ставится от имени исходного пользователя через UAC, но в CI запуск идёт сразу с правами администратора, и этот путь не проходит;
- работа загрузки NetLoom через корпоративный прокси с авторизацией и при запрете PowerShell групповой политикой — должна завершаться понятным сообщением, но в CI таких условий нет;
- проверка версии Windows проверена только на сборке скрипта: на Windows Server 2012 R2 установщик не запускался;
- пакеты Linux на Astra Linux, РЕД ОС, РОСА и ALT Linux не ставились — образов этих систем в CI нет; на совместимость указывают проверки на Debian (для Astra) и Fedora/Rocky (для РЕД ОС и РОСА); AppImage проверен только на Ubuntu.

- **Проверка типов**: main, общий код, данные, тесты — 0 ошибок; интерфейс — 0 ошибок с упрощёнными объявлениями React.
- **Интерфейс в Chromium** (предпросмотр с имитацией API): прежние 57 шагов без ошибок консоли; новые экраны мониторинга (карта, выбор узла, карточка с портами, редактор узла, режим редактирования карты, узлы, события, настройки) и UserGate (справочник, карточка, руководства) — в тёмной и светлой теме без ошибок консоли.

Найдено этой проверкой и исправлено:

- Карта шире окна открывалась в масштабе 100 % — правая часть была скрыта. Теперь при открытии карта вписывается по ширине.

- В демонстрационной карте два узла лежали друг на друге.

**Не проверено и требует проверки на вашей стороне:**

- **Мониторинг на реальной сети не запускался**: ни один настоящий коммутатор Cisco или OSNOVO, сервер видеонаблюдения, камера или UserGate не опрашивались по SNMP, трапы от настоящих устройств не принимались. SNMP проверен на имитации агента по протоколу; совместимость с конкретными прошивками не подтверждена. Начните с 2–3 узлов: SNMP на одном коммутаторе, выдерните кабель из свободного порта и проверьте, что пришёл трап.
- **Команды UserGate** взяты из документации производителя (UserGate NGFW 7.x) и на оборудовании не выполнялись; часть параметров в документации описана без полного примера — такие места помечены в карточках. В UserGate 6 синтаксис другой.
- Письма проверены на имитации SMTP-сервера; с настоящими почтовыми сервисами (корпоративный Exchange, Яндекс, Mail.ru) — нет.

## 3. Не проверялось

- **Реальные коммутаторы** — ни одно устройство (Cisco, SG300, HP ProCurve, Linksys, AT-8000S, Allied Telesis, Qtech, OSNOVO, TP-Link) не было доступно. Не проверены на оборудовании: синтаксис встроенных команд и профилей диагностики, распознавание приглашений и `--More--`, автоматический `enable`, отключение постраничного вывода, снятие конфигурации, разбор реальных MAC-таблиц и CDP/LLDP (разборщики проверены только на образцах вывода в тестах).
- **Реальные Linux-серверы** — кроме контейнера OpenSSH в CI.
- Старые SSH-реализации коммутаторов с устаревшими алгоритмами; Jump Host (в том числе перенос связи с Jump Host при импорте); удалённый и SOCKS-туннели; SFTP с большими файлами.
- Системные хранилища паролей на настоящих рабочих станциях (DPAPI, Keychain, GNOME Keyring / KWallet).
- Поведение SmartScreen и Gatekeeper с неподписанными сборками.
- Экранные дикторы, масштабирование HiDPI на разных ОС, длительная работа под нагрузкой.

Перед использованием в рабочей сети рекомендуется проверить на одном тестовом коммутаторе каждой модели: подключение, снятие конфигурации, 2–3 команды просмотра из справочника и диагностику порта.
