# Руководство пользователя NetAdmin Desk

## 1. Первый запуск

1. Установите программу (см. [BUILD.md → Неподписанные сборки](BUILD.md#неподписанные-сборки), если система предупреждает о неизвестном издателе).
   - **Windows** (10, 11, Server 2016 и новее): `NetAdminDesk-Windows-x64-Setup.exe`. На шаге «Дополнительно» можно отметить «Также установить браузер NetLoom» — по умолчанию галочка снята. Для NetLoom нужен интернет: он скачивается с GitHub во время установки и проверяется по контрольной сумме. Сам NetAdmin Desk ставится без интернета; если NetLoom скачать не удалось, установщик скажет почему, а NetAdmin Desk всё равно будет установлен. Шаги и результат установки NetLoom записываются в журнал `%TEMP%\NetAdminDesk-NetLoom.log` — это удобно при тихой установке (`/S /NETLOOM=1`), когда сообщений на экране нет.
   - **Linux:** `.deb` — Debian, Ubuntu, Mint, Astra (`sudo apt install ./netadmindesk-linux-amd64.deb`); `.rpm` — Fedora, RHEL, Rocky, Alma, РЕД ОС, РОСА (`sudo dnf install ./netadmindesk-linux-amd64.rpm`), openSUSE (`sudo zypper install --allow-unsigned-rpm ./netadmindesk-linux-amd64.rpm`); `.pacman` — Arch, Manjaro (`sudo pacman -U netadmindesk-linux-amd64.pacman`); `.AppImage` — любой дистрибутив без установки (`chmod +x`, затем запуск; на новых Ubuntu нужен `libfuse2t64`).
   - **macOS:** `NetAdminDesk-macOS-Universal.dmg`, перетащите программу в «Программы».
2. При первом запуске создаётся база данных и автоматически загружаются:
   - встроенный справочник (276 команд коммутаторов, 406 команд Linux, 210 команд SQL), 152 сценария, 56 руководств, профили диагностики;
   - обезличенные TXT-заметки по коммутаторам и по ACL/object-group (177 записей) — без исправления синтаксиса. Итоги разбора — на «Главной» и в «Настройки → База данных → Отчёты импорта TXT». Свои TXT-файлы можно добавить в «Настройки → Импорт и экспорт → Импорт TXT».
3. Выберите способ хранения паролей: «Настройки → Безопасность → Хранение паролей» (раздел 3).

Где лежат данные:

| ОС | Каталог |
|---|---|
| Windows | `%APPDATA%\NetAdmin Desk` |
| macOS | `~/Library/Application Support/NetAdmin Desk` |
| Linux | `~/.local/share/netadmin-desk` (или `$XDG_DATA_HOME/netadmin-desk`) |
| Переносимый режим | папка `netadmin-data` рядом с исполняемым файлом (создайте её — программа начнёт работать в ней) |

В каталоге: `netadmin.db` (база), `backups/` (конфигурации и файлы), `auto-backups/` (ежедневные копии базы), `session-logs/` (журналы сессий, если включены).

**Удаление программы.** В Windows деинсталлятор удаляет вместе с программой и весь каталог данных — об этом предупреждает его первая страница. Если данные понадобятся, сохраните их заранее: «Настройки → Импорт и экспорт → Зашифрованный экспорт всех данных», менеджер паролей — «Менеджер паролей → Экспорт». При обновлении программы данные остаются. Каталог переносимого режима не удаляется. В Linux и macOS менеджеры пакетов не трогают файлы в домашней папке: чтобы убрать данные, удалите каталог из таблицы выше вручную.

## 1а. Меню: простой и полный режим

Программа открывается в **простом режиме**: в меню на виду только основные разделы — Главная, Устройства, Сессии, инструменты (Сценарии, Диагностика), справочник (Коммутаторы, Linux, Базы данных, Обучение), Настройки. Остальное не пропало:

- **«Ещё N»** внутри группы раскрывает спрятанные разделы (Мои заметки, Избранное, Сетевые утилиты, История, Резервные копии).
- Заголовки групп **«Инструменты»** и **«Справочник»** сворачиваются щелчком. Открытый раздел виден и в свёрнутой группе.
- **«Показать всё»** внизу меню — полный режим: все разделы меню и все кнопки панели сессии на виду. Обратно — «Компактный вид».
- **Правая кнопка по пункту меню** — «Убрать в «Ещё»» или «Всегда показывать». Значок ползунков внизу меню (или Ctrl+K → «настроить меню») — окно настройки всех пунктов сразу.
- **Ctrl+K** находит не только команды, но и разделы и действия: «калькулятор», «разделить экран», «подключиться», «только чтение», «тема». При пустом запросе показаны быстрые действия.

В простом режиме на панели сессии видны «Справочник» и «Окно команд», остальные кнопки — в меню «⋯ Ещё»; в карточке устройства редкие поля свёрнуты. Режим меняется и в «Настройки → Внешний вид».

## 2. Устройства

«Устройства → Добавить» (или Ctrl+N). Вкладки:

- **Основное** — название, тип (Cisco, SG300, HP ProCurve, Linksys, AT-8000S, Allied Telesis, Qtech, OSNOVO, TP-Link, Linux, «другое»), **как подключаться** (SSH, Telnet или COM-порт), адрес, порт, логин; в блоке «Модель, группа, расположение, цвет, описание» — производитель, модель, версия ОС, группа, расположение, теги, **цвет метки** (полоска на вкладке сессии: например, красный для «боевых» устройств), описание. Для Linux — дистрибутив, назначение сервера, заметки о службах.
- **Telnet** — только для старого оборудования без SSH: данные и пароль передаются без шифрования, программа предупреждает об этом в карточке, на вкладке и на панели сессии. Порт по умолчанию 23. Если логин и пароль сохранены, программа сама ответит на «Username:» и «Password:».
- **COM-порт** — консольный кабель (RJ-45/DB9 или USB). Кнопка «Найти» показывает подключённые порты (COM3, /dev/ttyUSB0…), скорость обычно 9600 (у части новых — 115200), формат 8N1. Логин вводится в терминале. Подробно — руководство «Консольный кабель» в «Обучении».
- **Подключение и авторизация** — пароль, ключ (с парольной фразой или без), SSH-агент, keyboard-interactive; пароль `enable`.
- **Дополнительные параметры** (на вкладке «Подключение») — **команды после входа** (по одной на строку, например `terminal length 0`, `show clock`: отправляются видимо в терминал и проверяются режимом «Только чтение»), Jump Host (только SSH), автоматический `enable`, отключение постраничного вывода после входа, keepalive, тайм-аут, режим «Только чтение» для устройства, **устаревшие алгоритмы SSH** (только для этого устройства — для старых коммутаторов с `diffie-hellman-group1-sha1`, `ssh-rsa`, CBC-шифрами).

Группы и папки — слева в разделе «Устройства». Импорт устройств из CSV и `~/.ssh/config` — кнопка «Импорт» (с предварительным просмотром; пароли из CSV импортируются только при явной отметке). В CSV можно указать столбцы `protocol` (ssh / telnet / serial) и `baud`.

### Перенос устройств на другой компьютер

1. На этом компьютере: «Устройства» → **«Экспорт»** (или Ctrl+K → «экспорт устройств»).
2. Выберите, какие устройства: все, показанные в списке (например, текущая группа) или только выбранное. Узлы-посредники (Jump Host), через которые они подключаются, добавятся сами.
3. Формат — **«Файл переноса NetAdmin Desk» (.nadevices)**: все настройки подключения, группы и папки, цвета, команды после входа. По желанию:
   - **ключи хостов** — на новом компьютере не придётся заново подтверждать отпечатки;
   - **сохранённые пароли** — тогда задайте пароль файла (не короче 8 символов): весь файл шифруется (AES-256-GCM, ключ через scrypt). Без пароля файла пароли в файл не записываются. Пароль файла передайте отдельно от самого файла.
4. Скопируйте файл на другой компьютер (флешка, сетевая папка, почта).
5. На другом компьютере: «Устройства» → «Импорт» → **«С другого компьютера»** → «Выбрать файл…». Если файл зашифрован, введите его пароль. Программа покажет список: какие устройства новые, какие уже есть (их можно оставить как есть или обновить), есть ли пароли. Ключи хостов добавляются только новые: если ключ в файле отличается от уже известного, он **не заменяется** (это может быть подмена) — программа покажет отпечаток при подключении. Пароли импортируются только с отдельной галочкой и только если на этом компьютере настроено хранилище паролей.

Что не переносится: файлы SSH-ключей (скопируйте их отдельно и при необходимости укажите новый путь в карточке), номер COM-порта может отличаться. Вариант **«Таблица CSV»** — для Excel и учёта: основные поля без паролей; такая таблица читается обратно через «Импорт → Таблица CSV». Перенос всех данных программы сразу (команды, сценарии, заметки, настройки) — «Настройки → Импорт и экспорт», см. [MIGRATION.md](MIGRATION.md).

Тип устройства определяет платформу: от неё зависят проверка совместимости команд, отключение постраничного вывода, формат MAC-адреса в шаблонах и профиль диагностики.

## 3. Пароли

Пароли никогда не записываются в базу в открытом виде. Варианты:

| Режим | Как работает |
|---|---|
| Системное хранилище | Windows DPAPI, macOS Keychain, Linux libsecret (GNOME Keyring / KWallet) через `safeStorage`. Выбирается автоматически, если доступно |
| Мастер-пароль | AES-256-GCM, ключ из мастер-пароля через scrypt. Мастер-пароль не сохраняется: после запуска хранилище нужно разблокировать |
| Не хранить | Пароль запрашивается при каждом подключении |

На Linux без работающей связки ключей (backend `basic_text`) системное хранилище считается небезопасным и не используется — программа предложит мастер-пароль или запрос при подключении.

## 4. Сессии: SSH, Telnet, COM-порт

- Подключение: двойной щелчок по устройству, кнопка «Подключить», Ctrl+K → устройство → Ctrl+Enter.
- **Быстрое подключение по адресу**: «+» на панели вкладок (или Ctrl+K → «подключиться») и сразу адрес: `admin@10.0.0.1`, `10.0.0.1:2222`, `telnet://10.0.0.2`, `COM3`. Создаётся устройство с меткой «быстрое подключение» — потом укажите в нём тип, чтобы справочник и диагностика подбирали правильные команды.
- **Первое подключение**: показывается отпечаток ключа хоста (SHA256). Сверьте его с устройством (`ssh-keygen -lf /etc/ssh/ssh_host_*_key.pub` на Linux; на коммутаторах — команда показа ключа SSH) и нажмите «Доверять и подключиться».
- **Ключ изменился**: подключение блокируется, показываются старый и новый отпечатки. Заменить ключ можно только явно, отметив «Я сверил новый отпечаток». Причины — переустановка ОС, замена оборудования… или атака «человек посередине».
- Вкладки: Ctrl+Tab, Alt+1…9; закрыть — Ctrl+Shift+W или средняя кнопка мыши. **Правая кнопка на вкладке** — меню как в браузере: переподключиться, ещё одна сессия к этому устройству, закрыть, закрыть другие вкладки, вкладки слева, вкладки справа, отключённые, все. Повторное подключение — кнопка ↻.
- **Не подключается?** Кнопка **«Проверка связи»** над терминалом проверяет без входа на устройство: найдено ли имя в DNS, открыт ли TCP-порт, отвечает ли SSH-сервер приветствием — и пишет, на каком шаге проблема. Расшифровка сообщений — руководство «Не удаётся подключиться по SSH» в разделе «Обучение».
- Поиск в выводе — Ctrl+Shift+F. Копирование/вставка — Ctrl+Shift+C / Ctrl+Shift+V (macOS: ⌘C / ⌘V). При вставке нескольких строк программа спрашивает подтверждение.
- Панель справочника рядом с терминалом — Ctrl+\\ или кнопка «Справочник».
- Кнопки над терминалом: «Справочник», «Окно команд», «Разделить экран», enable-пароль, «Сохранить конфигурацию» (резервная копия), «Файлы (SFTP)» (Linux), «Туннели» (только SSH), «Диагностика», «Проверка связи». В простом режиме часть из них — в меню «⋯ Ещё».
- **Разделить экран**: 2–4 сессии рядом (кнопка, Ctrl+K → «разделить» или правая кнопка по вкладке → «Показать рядом с текущей»). Щелчок по панели делает её активной; ⤢ — оставить только эту сессию, ✕ — убрать панель.
- **Ввод во все**: в разделённом экране всё, что печатаете, уходит во все видимые панели. Включается с подтверждением, пока режим активен — красная полоса со списком устройств. Синтаксис команд у производителей разный — проверяйте, что команда подходит каждому.
- **Окно команд** (как Command window в SecureCRT): поле внизу для одной или нескольких строк. Enter — отправить, Shift+Enter — новая строка, Tab — подставить подсказку из справочника, ↑ — история. «Куда»: текущая сессия, все панели экрана или все подключённые. Риск оценивается до отправки; изменяющие команды в несколько сессий сразу запрещены, пока в «Настройки → Безопасность» не разрешено массовое выполнение.
- **Подсветка вывода**: up / connected / forwarding — зелёным, down / err-disabled / failed и ненулевые счётчики ошибок — красным, notconnect / disabled / administratively down — жёлтым, IP и MAC — голубым, интерфейсы — фиолетовым. Текст не меняется. Выключается в меню «⋯ Ещё → Вид» или в «Настройки → Терминал».
- **Панель быстрых команд**: «⋯ Ещё → Панель быстрых команд» — над терминалом кнопки с командами, отмеченными звёздочкой, для платформы текущего устройства.
- **Ctrl + колесо мыши** над терминалом — размер шрифта.
- Telnet и COM-порт: SFTP, туннели и SSH exec (отдельный канал для диагностики Linux) недоступны — команды выполняются в терминале. «Проверка связи» для Telnet проверяет порт 23, для COM-порта подсказывает, что проверить (кабель, номер порта, скорость).
- Тип терминала: `vt100` для коммутаторов, `xterm-256color` для Linux.

### SFTP и туннели

SFTP (для Linux-сессий): просмотр каталогов, загрузка и скачивание, создание, переименование и удаление (с подтверждением).

Туннели: локальный (`-L`), удалённый (`-R`), динамический SOCKS5 (`-D`). Порт `0` — система выберет свободный порт. Jump Host задаётся в карточке устройства.

## 4а. Сетевые утилиты

Раздел «Инструменты → Сетевые утилиты» (в простом режиме — в «Ещё» или Ctrl+K → «калькулятор» / «ping» / «ключ»):

- **Калькулятор подсетей** — адрес с маской в любом виде (`/26`, `255.255.255.192`, wildcard `0.0.0.63`): адрес сети, широковещательный, диапазон узлов, их число, тип адреса (частный, публичный, CGNAT…), деление сети на подсети, подбор префикса по числу узлов, «входит ли адрес в сеть», готовые строки для интерфейса Cisco, ACL и Linux, шпаргалка по маскам.
- **MAC-адреса** — один адрес во всех форматах производителей (с указанием, у каких коммутаторов какой формат), признаки multicast и «случайного» MAC; поиск всех MAC в вставленном тексте.
- **Ping, трассировка, порты** — проверки с этого компьютера. Показывается точная выполняемая команда (`ping -n 4 …` в Windows, `ping -c 4 …` в Linux и macOS; `tracert` / `traceroute`). Проверка TCP-портов: «открыт», «закрыт» (служба выключена) или «нет ответа» (фильтруется).
- **SSH-ключи** — создание ключа ed25519 (приватный ключ записывается только в выбранный файл с правами 600, открытый — рядом, `.pub`), установка открытого ключа на подключённый Linux-сервер через окно проверки команды, переключение устройства на вход по ключу.

## 5. Справочник команд

- Группа «Справочник» в меню: «Коммутаторы» (TXT-заметки и встроенные команды 9 платформ), «UserGate» (межсетевой экран UserGate NGFW), «Linux», «Базы данных» (SQL), «Обучение» (руководства), «Мои заметки», «Избранное». Фильтры: платформа/производитель (для SQL — СУБД), категория, риск, источник, «Требует проверки», избранное.
- **«Только простые команды»** — 301 базовая команда с подробными пояснениями для тех, кто только начинает: как перейти в каталог, отредактировать файл, перезагрузить сервер, войти в режим настройки коммутатора, сохранить конфигурацию и т. п.
- Встроенные команды для всех платформ, кроме Cisco IOS, помечены «Требует проверки»: синтаксис зависит от модели и прошивки, на реальном оборудовании они не проверялись. Подсказка `?` на коммутаторе покажет точный синтаксис.
- Без поискового запроса первыми показываются записи из TXT-заметок — в порядке файла.
- Карточка показывает: команду (каждую строку можно скопировать или выполнить отдельно), режим CLI, описание, пояснения к строкам, пример вывода, предупреждения, исходный текст из файла, номер строки, источник. Для Linux — синтаксис, параметры, примеры, нужны ли права root, связанные команды, ссылка на man.
- **Требует проверки** — запись взята из TXT-файла как есть, но в ней замечена возможная ошибка (например, `counerts` вместо `counters`, команда глобального режима с приглашением `(config-if)`, пометка «взят из статьи»). Ничего не исправляется автоматически. После проверки нажмите «Отметить «Проверено мной»».
- **Производитель не указан** — записи из начала файла до `###SG300###`. Синтаксис похож на Cisco IOS, но это предположение, поэтому при выполнении на устройстве программа предупреждает о возможной несовместимости.
- Записи с учётными данными (например, пароли по умолчанию) скрыты из поиска и карточек; показать их можно в «Настройки → Безопасность».
- «Редактировать» — изменение записи (встроенные и импортированные записи после правки помечаются как изменённые пользователем и не перезаписываются обновлениями справочника). «Удалить» для встроенных записей — скрытие, вернуть можно в «Настройки → База данных».
- Свои заметки — раздел «Мои заметки».
- Справочник обезличен: в нём нет адресов, имён устройств и названий конкретной организации — его можно передавать коллегам. В примерах — `10.10.x.x`, `192.168.1.x`, `SW-ACCESS-1`, `shop`, `app_user`.

### Базы данных (SQL)

Раздел «Справочник → Базы данных» — 210 команд для **MySQL, MariaDB и PostgreSQL**: подключение (локально, по сети, через сокет, файлы ~/.my.cnf и ~/.pgpass), базы, таблицы, индексы, пользователи и права, резервные копии и восстановление, мониторинг, блокировки и долгие запросы, обслуживание, настройки, репликация, служба.

- Фильтр **«СУБД»**: «Общий SQL» (работает везде), «MySQL / MariaDB», «PostgreSQL».
- В карточке указано, **где вводить** команду: в терминале Linux (например, `mysqldump`, `pg_dump`) или внутри клиента базы — сначала `sudo mysql` или `sudo -u postgres psql` (окно выполнения напомнит об этом). Блок **«Отличия СУБД и версий»** показывает, как то же делается в другой СУБД.
- **MySQL и MariaDB** почти одинаковы — записи «MySQL / MariaDB» подходят обеим. **PostgreSQL** заметно отличается в служебных командах, пользователях, правах и настройках. Таблица соответствий — руководство «Отличия синтаксиса: MySQL, MariaDB и PostgreSQL» в «Обучении».
- Оценка риска учитывает SQL: `SELECT`/`SHOW` — просмотр, `UPDATE`/`DELETE` без `WHERE`, `DROP`, `TRUNCATE`, восстановление дампа поверх базы — опасные и критичные.

### UserGate NGFW

Раздел «Справочник → UserGate» — 79 команд CLI межсетевого экрана UserGate NGFW 7.x по документации производителя. Все записи помечены «Требует проверки»: на реальном оборудовании в программе они не проверялись, а в UserGate 6 и старше CLI устроен иначе.

- **Подключение.** Тип устройства «UserGate NGFW» сам подставляет SSH-порт **2200** и пользователя **Admin**. Доступ к CLI включается в свойствах зоны: «Контроль доступа» → «CLI по SSH».
- **Режимы.** После входа — режим диагностики (`Admin@узел>`): show, ping, traceroute, dig, netcheck. `configure` — режим конфигурации (`Admin@узел#`): show, set, create, delete, edit, execute; `exit` — обратно. В карточке записи указано, в каком режиме её вводить.
- **Категории:** основы CLI, интерфейсы и VLAN, ARP, маршруты и шлюзы, OSPF/BGP, зоны и доступ к управлению, правила межсетевого экрана и NAT (UPL), трафик и соединения, захват пакетов и трассировка, СОВ, ping/traceroute/DNS, LLDP, NTP, кластер, SNMP, резервные копии, перезагрузка.
- **Риск** оценивается с учётом платформы: `shutdown` у UserGate — «Критично» (выключение межсетевого экрана), `delete … all` — «Критично», изменения зон, интерфейсов, маршрутов и правил — «Опасно», `configure` и `edit` — «Просмотр». Многострочное правило UPL (строки с `\` в конце) оценивается целиком.
- Справа, пока команда не выбрана, — ссылки на руководства по UserGate.

### Шаблоны

Параметры записываются как `{{INTERFACE}}`, `{{VLAN}}`, `{{IP}}`, `{{MAC}}`, `{{PORT}}`, `{{ACL_NAME}}`, `{{SERVICE}}`, `{{USERNAME}}`, `{{FILE}}`, `{{DIRECTORY}}` и т. д.; значение по умолчанию — `{{VLAN:1}}`. «Создать шаблон» предлагает заменить конкретные значения команды параметрами. Значения проверяются (IP, VLAN 1–4094, MAC); MAC приводится к формату платформы. Свои параметры — «Настройки → Параметры шаблонов».

### Обучение

Раздел «Обучение» — 66 руководств, которые работают без интернета: первые шаги, основы сетей (IP и маска, MAC и ARP, VLAN/access/trunk, петли и STP, PoE, агрегация, CDP/LLDP, ошибки портов, имена портов у разных производителей), задачи на коммутаторах (найти устройство по MAC, перевести порт в VLAN, добавить VLAN на trunk, перезагрузить камеру по PoE, сохранить конфигурацию, заменить коммутатор, безопасно менять настройки удалённо, ACL), мониторинг сети (как устроен, SNMP и трапы на устройствах, «трапы не приходят», почта), UserGate NGFW (первое подключение, диагностика по шагам, правила и NAT, SNMP, кластер, «пропал доступ к веб-консоли»), Linux для начинающих, базы данных (с нуля, отличия синтаксиса, резервные копии, «не подключиться», «тормозит», «много места», «не запускается», репликация), решение проблем и словарь терминов. В блоках с командами есть «Копировать» и «Выполнить…» — команда откроется в окне выполнения с проверкой совместимости и подтверждением. Примеры вывода и команды для других программ (PowerShell, ssh) помечены «Пример» и только копируются. Руководства находятся и через Ctrl+K.

## 6. Выполнение команды на устройстве

«Выполнить на устройстве» в карточке, Ctrl+Enter в быстром поиске, кнопка ▷ у строки.

Окно выполнения показывает:

1. команду и её платформу;
2. **целевое устройство** — открытую сессию или «подключиться и выполнить»;
3. **совместимость**: если платформа команды не совпадает с устройством, отправка запрещена, пока вы не отметите, что отправляете осознанно; для записей без производителя — предупреждение;
4. поля параметров шаблона;
5. **итоговую команду**, которую можно поправить вручную (риск пересчитывается);
6. уровень риска: «Просмотр», «Изменение», «Опасно», «Критично» — и что именно в команде опасно;
7. подтверждение для изменяющих и многострочных команд.

Команда отправляется в терминал видимо — вы видите ввод и ответ устройства. Фоновой отправки нет. Всё отправленное записывается в «Историю» (пароли маскируются). «Копировать» не выполняет команду.

Режим **«Только чтение»** (глобальный — в настройках, или для отдельного устройства) блокирует отправку изменяющих команд из справочника, сценариев и диагностики. Ввод вручную в терминале не фильтруется.

## 7. Быстрый поиск (Ctrl+K)

Ищет по командам коммутаторов и Linux, руководствам, устройствам, сценариям и заметкам. Можно писать как думаешь:

- **падежи и словоформы** — «таблицу маков», «ошибки на портах», «перезагрузить сервер»;
- **русские названия программ и понятий** — «апач» (apache), «нджинкс» (nginx), «докер», «постгрес», «мускул» (mysql), «влан», «транк», «пое»;
- **запись по звучанию** — «курл» → curl, «линукс» → linux;
- **опечатки** — «ошибкии», «interfase»;
- **вопросы** — «как удалить папку», «как найти в какой порт подключен компьютер»: служебные слова («как», «где», «в») не мешают;
- **неверную раскладку** — «ырщц мдфт» → show vlan.

Первой идёт группа с лучшими совпадениями; результаты, где совпали не все слова, показаны отдельно в конце. Фильтры — чипы групп, производитель, риск, источник, избранное. Enter — открыть, Ctrl+Enter — выполнить или подключиться.

Если в терминале Ctrl+K нужен для CLI (удаление до конца строки), включите «Передавать Ctrl+K в терминал» — поиск откроется по Ctrl+Shift+K.

## 8. Диагностика

### Коммутаторы и UserGate

26 задач для коммутаторов: состояние порта, конфигурация порта, ошибки, счётчики, обзор всех портов, кто подключён к порту, поиск MAC, ARP, VLAN и список VLAN, trunk, PoE, агрегирование, соседи CDP/LLDP, порты err-disabled, Spanning Tree, оптика SFP, тест медного кабеля, загрузка процессора, время и NTP, кто подключён к коммутатору, оборудование, память, журнал, текущая конфигурация. Для каждой платформы — свой профиль команд (в основном из TXT-заметок; редактируется на вкладке «Профили платформ», можно сбросить к исходному). Перед запуском показываются все команды; если команда в профиле изменяющая — отдельное подтверждение. Отчёт сохраняется и сравнивается с прошлым.

Для **UserGate NGFW** предлагаются только задачи, для которых есть команды (PoE, STP, VLAN-таблицы коммутатора и т. п. скрыты), и 5 задач межсетевого экрана: «Куда идёт трафик к адресу (маршрут)», «Доступен ли адрес с межсетевого экрана» (ping и трассировка с самого UserGate), «Соединения к адресу и от него» (ASSURED — ответ есть, UNREPLIED — нет), «Адреса, заблокированные СОВ», «Состояние кластера (HA)». Все команды — режима диагностики, только просмотр.

### Linux-серверы

27 системных проверок: система, процессор, память, нехватка памяти (OOM), диски, inode, монтирование и сетевые папки, RAID, сеть, маршруты, DNS, время, службы, веб-серверы, базы данных, журнал, ошибки ядра и оборудования, SSH, неудачные входы, пользователи, автозагрузка, порты, firewall, обновления, нужна ли перезагрузка, зависшие процессы, Docker. Готовые наборы: общая диагностика, быстрая проверка, «сервер тормозит», проблемы с дисками, безопасность, веб/базы/Docker, после сбоя или перезагрузки. Каждая показывает команды, критерии оценки, исходный вывод и результат («Норма», «Внимание», «Проблема», «Нет данных»). Команды только для чтения, выполняются отдельным каналом `exec` и дублируются в терминал сессии. Сведения, требующие root, отмечаются в отчёте. Повторный запуск сравнивается с предыдущим (например, рост заполнения диска).

### Базы данных: MySQL, MariaDB, PostgreSQL

13 проверок и 7 наборов в группе «Базы данных» списка задач: «MySQL / MariaDB: полная проверка», «PostgreSQL: полная проверка», «База данных тормозит», «К базе не подключиться / Too many connections», «База занимает много места / кончается диск», «Репликация баз данных», «База упала или перезапускалась», а также «Базы данных: быстрая проверка».

| Проверка | MySQL / MariaDB | PostgreSQL |
|---|---|---|
| Служба и журнал | состояние mariadb/mysql, перезапуски, OOM; ошибки, повреждения, «Too many connections» в журнале | кластеры (pg_lsclusters), FATAL/PANIC, нехватка соединений и неудачные входы в журнале, OOM |
| Подключения и нагрузка | занято соединений из max_connections, пик, время работы, медленные запросы, bind_address | занято соединений, «idle in transaction», попадание в кэш, deadlock, временные файлы |
| Долгие запросы и блокировки | запросы дольше минуты, транзакции дольше 5 минут, ожидание metadata lock | запросы дольше минуты, кто кого блокирует, простаивающие транзакции |
| Место на диске | раздел каталога данных, размер баз, binlog | раздел каталога данных, pg_wal, размер баз |
| Репликация | потоки IO/SQL, отставание, последняя ошибка | реплики, отставание, неактивные слоты, удерживающие WAL |
| Прочее | буфер InnoDB и ОЗУ, кодировка, таблицы MyISAM | autovacuum, раздувание таблиц, возраст транзакций |

Все запросы только читают и выполняются **без sudo**. Под root программа входит в MySQL / MariaDB через сокет, а в PostgreSQL — от имени postgres (`runuser`). Под обычным пользователем нужен `~/.my.cnf` или `~/.pgpass` (пользователю мониторинга достаточно прав PROCESS, REPLICATION CLIENT и SELECT в MySQL — в MariaDB 10.5+ для состояния реплики ещё SLAVE MONITOR — или роли pg_monitor в PostgreSQL); если доступа нет, отчёт так и скажет и подскажет, что сделать. Если СУБД на сервере нет, её проверки отмечаются «не установлен». Находки содержат готовые команды (например, отмена запроса), но сами ничего не выполняют.

### Поиск MAC

Введите MAC в любом формате. Программа ищет его в MAC-таблице выбранного коммутатора, определяет порт; если за портом другой коммутатор (по CDP/LLDP и вашим устройствам), предлагает перейти к нему — так строится цепочка до конечного порта. Можно показать ARP, чтобы узнать IP.

## 8а. Мониторинг сети

Раздел «Инструменты → Мониторинг» показывает, какие устройства сейчас в сети, а какие нет, — на карте и списком. Программа опрашивает узлы сама; мониторинг работает, **пока программа запущена**, поэтому ставьте её на компьютер со статическим IP, который не выключается.

### Узлы

«Добавить узел»: название, IP-адрес или имя, тип (коммутатор, сервер видеонаблюдения, камера, межсетевой экран…), способ проверки:

| Проверка | Что делает | Что нужно на устройстве |
|---|---|---|
| Ping | Узел отвечает на ping — в сети | Ничего |
| SNMP | Запрос имени и времени работы (v1/v2c); видны перезагрузки и порты. Нет ответа по SNMP — проверяется ping, узел жёлтый | Community только для чтения, опрос разрешён с адреса этого компьютера |
| TCP-порт | Подключение к порту (80, 443, 554 — RTSP…). Порт не отвечает, а ping есть — узел жёлтый: служба недоступна | Служба слушает порт |

Интервал проверки задаётся для узла (0 — как в настройках, по умолчанию 30 секунд). Community хранится в защищённом хранилище; если надёжного хранилища нет, сохранить её нельзя — настройте мастер-пароль.

Много узлов сразу — «Списком»: по строке на узел (`имя; адрес; тип` или просто адрес), диапазон `192.168.5.1-20` добавит 20 узлов. Уже заведённые устройства — «Из устройств». Повторяющийся адрес программа подсветит.

### Состояния

- **Зелёный — в сети**, **жёлтый — есть проблемы** (SNMP или TCP-порт не отвечает при живом ping, пришёл трап «порт отключился»), **красный — не в сети**, серый — ещё не проверялся или пауза.
- «Не в сети» объявляется после нескольких неудач подряд (по умолчанию 2; после первой неудачи — перепроверка через 5 секунд). Одна потерянная проверка тревоги не вызывает.
- Перезагрузка определяется по уменьшению времени работы (SNMP) и по трапам coldStart/warmStart.

### Карта

«Карта» → «Создать карту»: узлы раскладываются сеткой. «Редактировать» — перетаскивайте узлы (привязка к сетке), «Связь» — щёлкните два узла, чтобы соединить их линией (щелчок по линии в этом режиме удаляет её), «Добавить все» — узлы, которых ещё нет на карте, «Подложка…» — картинка до 8 МБ (план этажа, схема). Изменения сохраняются сами. Карт может быть несколько.

Масштаб — кнопками или Ctrl + колесо мыши; карта шире окна при открытии вписывается по ширине. Узел, который не в сети, пульсирует красным, а линия к нему становится красной пунктирной. Щелчок по узлу — краткая карточка справа, «Подробнее» — состояние, время работы, **таблица портов по SNMP** (имя, описание, состояние, скорость) и история.

### SNMP-трапы

«Настройки → SNMP-трапы» → «Принимать SNMP-трапы» (UDP 162, адрес 0.0.0.0 — все интерфейсы). На устройствах укажите адрес этого компьютера как получателя трапов — адреса показаны там же. Трапы v1, v2c и inform:

- **linkDown / linkUp** — коммутатор становится жёлтым, в карточке и на карте видно, какой порт упал (имя и описание порта запрашиваются по SNMP), до трапа «порт включился» или сброса вручную;
- **coldStart / warmStart** — перезагрузка;
- остальные — в журнале событий.

Можно принимать трапы только с указанной community и записывать трапы от адресов, которых нет в мониторинге. Если приём не запускается, программа объяснит почему: порт занят «Службой ловушек SNMP» Windows, нет прав на порт ниже 1024 (Linux, macOS) или адрес недоступен. Подробно и с командами для Cisco, OSNOVO, Linux и UserGate — руководства «Настройка SNMP и трапов на устройствах» и «Трапы не приходят» в «Обучении».

### Уведомления и почта

- **На рабочем столе** — когда узел пропал, вернулся (можно отключить) или перезагрузился; если событий много сразу, приходит одно общее уведомление. Щелчок открывает «Мониторинг».
- **Письма** — «Настройки → Письма на почту»: SMTP-сервер, шифрование (STARTTLS 587, TLS 465, без шифрования 25), логин и пароль (хранится в защищённом хранилище), отправитель, получатели. События копятся заданное время (по умолчанию 60 секунд) и уходят одним письмом. «Отправить тестовое письмо» покажет ошибку сервера, если что-то не так.

### Работа в фоне

«При закрытии окна продолжать мониторинг» — окно прячется в область уведомлений, проверки продолжаются (меню значка: открыть программу или мониторинг, сколько узлов не в сети, выход; та же сводка — во всплывающей подсказке значка). «Запускать вместе с Windows» — программа стартует скрыто при входе в систему. Красный счётчик в меню показывает, сколько узлов не в сети.

### Узлы и события

«Узлы» — таблица с поиском и фильтром (все, проблемы, не в сети): проверить сейчас, подробнее, изменить, удалить. «События» — журнал (пропал, вернулся, перезагрузка, трапы, письма) с фильтрами; хранятся последние 20 000 событий. «Пауза» в заголовке останавливает все проверки.

## 8б. Менеджер паролей

«Инструменты → Менеджер паролей» — хранилище логинов, паролей и заметок по образцу KeePass: веб-интерфейсы, учётные записи, Wi-Fi, ключи восстановления. Пароли устройств для подключения по SSH по-прежнему хранятся в карточке устройства («Настройки → Пароли»); менеджер паролей — отдельное хранилище со своим мастер-паролем.

### Первый запуск

Придумайте **мастер-пароль** (не короче 8 символов; лучше — фраза из нескольких слов) и введите его дважды. Индикатор покажет примерную стойкость. Мастер-пароль нигде не сохраняется: **если его забыть, записи не восстановить**. Тогда останется только «Забыли мастер-пароль?» → удалить все записи и создать хранилище заново (и вернуть записи из файла .nadpass, если он есть).

### Записи и папки

- **Добавить** — название, логин, пароль, адрес, папка, заметки, метки, избранное. «Сгенерировать» открывает генератор: длина 8–64, строчные, прописные, цифры, символы, «без похожих» (I l 1 O 0 o |). Символы, которые неудобно вводить в CLI (кавычки, `\`, пробел, `?`), генератор не использует.
- **Папки** — слева: «+» создаёт, двойной щелчок или карандаш — переименовать, корзина — удалить (записи останутся без папки).
- **Поиск** — по названию, логину, адресу, папке и меткам; сортировка по названию или по дате изменения.
- **Карточка записи** — логин и адрес с кнопками копирования, пароль скрыт: «Показать» (скроется сам через 30 секунд), «Скопировать». Ссылки http(s) открываются в браузере.
- **Двойной щелчок** по записи в списке копирует пароль.
- **История паролей** — при смене пароля прежний сохраняется (до 10 последних); его можно показать и скопировать в карточке.

### Буфер обмена

Скопированный пароль удаляется из буфера обмена через 20 секунд (настраивается) — если вы за это время не скопировали что-то своё. При блокировке менеджера и выходе из программы скопированный пароль тоже удаляется. Логин и адрес копируются без очистки.

### Проверка паролей

«Слабые пароли» — легко подбираемые (короткие, распространённые, из повторяющихся символов). «Повторяются» — один и тот же пароль в нескольких записях. В карточке такой записи — предупреждение, стойкость и сколько пароль не менялся. Оценка приблизительная.

### Блокировка

- «Заблокировать» — сразу; снова открыть — мастер-паролем.
- Автоматически: через 10 минут без действий в менеджере (1–60 минут или «не блокировать»), при блокировке экрана и переходе в сон; по желанию — при сворачивании окна или скрытии в область уведомлений. «Настройки» менеджера (слева внизу).
- После трёх неверных мастер-паролей подряд следующая попытка возможна через паузу (1, 2, 4… до 30 секунд).

### Экспорт

- **Зашифрованный файл .nadpass** — для резервной копии и переноса на другой компьютер. Пароль файла задаёте сами (не короче 8 символов). В файл попадают папки, все поля, избранное и история паролей.
- **CSV без шифрования** — для переноса в KeePass, KeePassXC, Bitwarden. Только после предупреждения и повторного ввода мастер-пароля. Столбцы: Group, Title, Username, Password, URL, Notes, Last Modified, Created. Удалите файл сразу после переноса.

Записи менеджера паролей не входят в «Перенос данных» (раздел 12): для них есть свой экспорт. В резервной копии базы данных они есть, но зашифрованы мастер-паролем.

### Импорт

«Импорт…» → файл:

- **.nadpass** — программа спросит пароль файла;
- **CSV** с заголовками — из KeePass, KeePassXC, Bitwarden, Chrome/Edge, Firefox, LastPass или своей таблицы (столбцы «Название; Логин; Пароль; Адрес; Заметки; Папка», разделитель «,», «;» или табуляция).

Программа покажет записи (без паролей) и откуда, судя по столбцам, выгружен файл. Записи с тем же названием, логином и адресом, что уже есть, помечены «уже есть» и не отмечены. Выберите нужные и куда класть: в папки из файла (недостающие создадутся) или все в одну папку. Файл .kdbx KeePass напрямую не открывается — выгрузите из KeePass CSV.

### Смена мастер-пароля

«Сменить мастер-пароль» — нужен текущий; все записи перешифровываются новым ключом. Ранее сохранённые файлы .nadpass открываются своим паролем файла, как и раньше.

## 9. Сценарии

Сценарий — последовательность шагов (команды или шаблоны) для одной или нескольких платформ. Встроено 162 сценария: для коммутаторов — диагностика порта и PoE-порта, поиск устройства по MAC и его IP, перевод порта в VLAN, добавление VLAN на trunk, создание VLAN, перезагрузка PoE-устройства, перезапуск порта, подпись порта, «растут ли ошибки», сохранение, бэкап на TFTP, обзор и проверка здоровья коммутатора, первичная настройка — для каждой платформы своим синтаксисом; для UserGate NGFW — 10 (обзор, «не открывается узел за межсетевым экраном», «нет интернета», кластер, блокировка СОВ, доступ к управлению, SNMP для мониторинга, правила, трассировка трафика узла, время); для Linux — 52 сценария (место на диске, тормозит сервер, нет сети, сайт не открывается, служба не запускается, обновление, пользователи, firewall, резервные копии баз и /etc, Docker, сертификаты, диски, swap и др.). Над списком есть поиск (понимает «перезагрузить камеру», «место на диске», «апач») и фильтр по платформе — показываются только сценарии для выбранной модели. Режимы:

- **пошаговый** — после каждого шага решение: продолжить, повторить, пропустить, остановить;
- **автоматический** — шаги идут подряд, опасные всё равно подтверждаются.

Сценарий с изменяющими шагами можно запустить только на одном устройстве, пока в настройках не разрешено массовое выполнение. Несовместимые платформы проверяются до запуска. Вывод каждого шага сохраняется.

## 10. Резервные копии конфигураций

- Коммутатор: «Резервные копии → Сохранить текущую конфигурацию» (или кнопка «Конфигурация» в сессии). Используется команда показа конфигурации платформы, постраничный вывод отключается. Если конфигурация не изменилась, это отмечается.
- Сравнение: отметьте две копии → «Сравнить выбранные». Можно игнорировать пробелы и служебные строки (время изменения, ntp clock-period).
- Linux: загрузка выбранных файлов и каталогов по SFTP (с файлом `MANIFEST.txt`), а также готовые команды `tar`, `dpkg --get-selections`, `rsync`.

Подробно о резервных копиях самой программы — [BACKUP.md](BACKUP.md).

## 11. История

Все отправленные команды: время, устройство, источник (справочник, сценарий, диагностика, ввод вручную…), риск, результат (отправлена, отменена, заблокирована). Строки, введённые после запроса пароля, не записываются; пароли в командах маскируются. Запись ручного ввода можно отключить в настройках.

## 12. Импорт и экспорт

«Настройки → Импорт и экспорт»:

- **Импорт TXT** — предварительный просмотр, отчёт (количество записей, нераспознанные строки, «Требует проверки», дубликаты), затем импорт. Поддерживаются UTF-8, UTF-16 и Windows-1251.
- **Экспорт TXT** — свои и импортированные записи в исходном виде.
- **JSON** — команды, сценарии, заметки, группы и устройства без паролей; при импорте отличающиеся записи не заменяются без вашего выбора.
- **Зашифрованный перенос (.nadx)** — всё, включая пароли, известные ключи хостов и настройки. См. [MIGRATION.md](MIGRATION.md).
- **Только устройства** (перенос списка на другой компьютер, CSV для Excel, импорт из CSV и `~/.ssh/config`) — кнопки «Экспорт» и «Импорт» в разделе «Устройства», см. раздел 2.

## 13. Горячие клавиши

| Клавиши | Действие |
|---|---|
| Ctrl+K | Быстрый поиск |
| Ctrl+Shift+K | Быстрый поиск, если Ctrl+K передаётся в терминал |
| Ctrl+N | Новое устройство |
| Ctrl+B | Свернуть боковую панель |
| Ctrl+\\ | Терминал + справочник |
| Ctrl+Tab / Ctrl+Shift+Tab | Следующая / предыдущая сессия |
| Alt+1…9 | Сессия по номеру |
| Ctrl+Shift+W | Закрыть сессию |
| Ctrl+Shift+F | Поиск в терминале |
| Ctrl+= / Ctrl+- / Ctrl+0 | Масштаб |
| Ctrl + колесо мыши над терминалом | Размер шрифта терминала |
| Правая кнопка по вкладке | Меню вкладок: закрыть слева/справа/другие, показать рядом |
| Правая кнопка по пункту меню | Закрепить раздел или убрать в «Ещё» |
| F1 | Справка по клавишам |

На macOS вместо Ctrl — ⌘.

## 14. Работа без интернета

Программа не обращается в интернет и не собирает телеметрию. Сеть используется только для подключений к вашим устройствам (SSH, Telnet), для проверок, которые вы запускаете сами в «Сетевых утилитах», и — если вы добавили узлы в «Мониторинг» — для опроса этих узлов (ping, SNMP, TCP), приёма трапов от них и отправки писем через указанный вами SMTP-сервер. Ссылки на man-страницы открываются во внешнем браузере только по вашему нажатию.
